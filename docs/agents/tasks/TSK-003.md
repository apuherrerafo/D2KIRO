## Contexto (ticket autocontenido)
Proyecto: dota2coach. `apps/engine` (Bun + SQLite/Drizzle, ver TSK-002) necesita poblar su cache
local desde la API pública de OpenDota (sin API key). Este trabajo corre **fuera del camino
caliente** del draft — el motor de sugerencias nunca debe llamar a la red directamente.

Depende de TSK-002 (esquema SQLite ya debe existir).

## Costura de prueba S6
- **Real en la prueba**: el mapeo de la respuesta de OpenDota y la escritura en SQLite.
- **Se reemplaza**: el cliente HTTP — usa respuestas de OpenDota grabadas en fixtures. Ninguna
  prueba de este ticket hace una llamada de red real.

## Qué construir
- `OpenDotaClient`: llama a `/heroes`, `/heroes/{id}/matchups`, `/heroStats` de OpenDota.
- Sincronizador que mapea las respuestas a las tablas `heroes`, `hero_matchups`,
  `hero_patch_stats` (esquema de TSK-002), registrando cada corrida en `meta_sync`.
- Ventana de frescura: **24 horas**. Se dispara al arrancar el motor si el cache está vencido, y
  manualmente vía `POST /api/meta/sync` (ese endpoint HTTP es de otro ticket — aquí solo la
  función de sincronización que ese endpoint invocará).

## Reglas de error (obligatorias, no opcionales)
- **429 de OpenDota**: reintento con espera creciente (1s, 4s, 16s), máximo 3 intentos. Si falla
  tras los 3, `meta_sync.status = 'failed'` y se sigue sirviendo el cache viejo.
- **OpenDota caído / sin internet**: idéntico — cache viejo sigue sirviendo.
- **Respuesta con forma inesperada**: se valida en el borde (es input externo); registros
  inválidos se descartan y se cuentan en `meta_sync.error`. La sincronización de **cada tabla es
  transaccional** — una escritura parcial nunca deja el cache a medias.
- **Héroe nuevo tras un parche**: entra en `heroes` en la siguiente sincronización; hasta
  entonces, eventos con ese id se rechazan aguas abajo (no es responsabilidad de este ticket).

## Aceptación
- Con fixtures grabados de OpenDota, la sincronización escribe correctamente en las 3 tablas y
  registra el resultado en `meta_sync`.
- Una fixture con un 429 simulado dispara los 3 reintentos con backoff y termina en
  `status: 'failed'` sin dejar filas a medias.
- Ninguna prueba de este ticket depende de red real.
