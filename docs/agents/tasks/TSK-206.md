de TSK-204. **9.1 no arranca hasta que esto cierre.**

## Alcance

1. Correr `scripts/eval/propose-golden-cases.ts` → revisar los ~30 candidatos propuestos.
2. Para cada caso aceptado, el usuario escribe las etiquetas **multi-label** (`excellent` /
   `acceptable` / `bad`, varios héroes por lista, `why` obligatorio por héroe) + `reasoningTags`.
   Casos que no aporten se descartan; se piden más de la propuesta si falta cobertura.
3. Resultado: `eval/golden/*.json` con **≥ 30 casos** que pasan `loadGoldenDataset` sin rechazos,
   con **≥ 1 caso por combinación `decisionContext` × estrato prioritario** y todos con `excellent`
   no vacío.
4. **Precondición cumplida antes de este paso**: Fase 8 commiteada (`TSK-183`→`TSK-192` + fix
   `validation.ts`). Correr `bun run eval` → `eval/baselines/v6-measured.json` con el `commit`
   apuntando a un árbol con Fase 8 integrada.
5. Correr `scripts/eval/gate.ts` (informativo) contra ese baseline y **anexar su salida a
   `journal.md`** con el formato estándar (`tool:evaluation-engineer` o `tool:build`,
   `result:info`).
6. `PROGRESS.md`: marcar 9.0 como cerrado, `SIGUIENTE PASO` = `/blueprint` angosto de 9.1 (Sonnet).

## Criterios de aceptación

1. `bun test` incluye una prueba de humo que carga `eval/golden/` **real** con `loadGoldenDataset`
   y verifica `rejected.length === 0` y `cases.length >= 30` — **excepción explícita** a la regla
   "ninguna prueba lee el Golden real": esta prueba valida la *forma*, no asume *contenido* (no
   comprueba qué héroe está en qué lista). Documentada como tal.
2. Cobertura: existe ≥ 1 caso para cada `decisionContext` y para los estratos `hard_counter`,
   `role_scarcity`, `team_needs`, `historical_failure` como mínimo.
3. `eval/baselines/v6-measured.json` existe, versionado, con `commit` resoluble a un árbol que
   contiene Fase 8.
4. La salida de `gate.ts` está en `journal.md`.
5. `PROGRESS.md` actualizado por este ticket (excepción al "no se edita a mano": lo edita el cierre
   de fase, igual que hace `/compass`).
