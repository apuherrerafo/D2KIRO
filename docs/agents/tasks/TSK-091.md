## Origen

Continuación directa de TSK-090 (motor Pro-Drafter v1.0, dark launch). El usuario pidió, en la
misma sesión: (1) un script CLI manual (`scripts/test-pipeline.ts`, `bun run draft:test`) que
corra `runProDrafterPipeline` sobre 3 escenarios sintéticos y muestre el Top 3 con desglose de
señales; (2) exponer el endpoint experimental `POST /api/v1/draft/pro-recommendations` tras
`ENABLE_PRO_DRAFTER`, sin alterar el comportamiento v5 cuando el flag está apagado; (3) confirmar
que `bun test` sigue en verde sin romper el aislamiento de `pipeline/`.

## Decisión que activa el dark launch -- fuera de `/blueprint`, con su propio gate

TSK-090 había dejado documentado que activar el pipeline (conectarlo a algo bajo `server/`) es
"una decisión aparte, con su propio gate", verificado con un test que confirmaba cero imports de
`pipeline/` desde `server/`. La pieza 2 de este ticket cruza esa frontera a propósito. Antes de
tocar `server/` se preguntó al usuario explícitamente (`AskUserQuestion`, no asumido) cómo
proceder dado que ni existe un `/blueprint` formal ni un ticket previo para esta activación --
confirmó "tu pedido es el gate, procede". Esta sesión documenta esa confirmación como la decisión
explícita que TSK-090 pedía.
