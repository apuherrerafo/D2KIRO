## Especificación de `team_synergy` (peso v1: **0.20**)
- Fuente: **heurística** (decisión D2 de `docs/specs/SPEC.md` §0 — OpenDota no expone sinergia
  medida entre aliados de forma limpia; no se usa STRATZ ni ninguna dependencia nueva).
- Cálculo: cobertura de capacidades faltantes en el equipo propio (`state.picks` del lado de
  `state.localSide`), usando `roles[]` de OpenDota (la misma columna JSON de la tabla `heroes`,
  ver TSK-002): control, iniciación, aguante, empuje, curación/soporte. Puntúa alto lo que llena
  un hueco de capacidad que el equipo propio todavía no tiene cubierto.
- **`sampleSize: 0` siempre** — es una heurística, no un dato medido. La UI (ticket aparte) la
  marca como señal estimada, no medida — este ticket solo garantiza que `sampleSize` sea
  consistentemente `0`.
- `explanation`: frase corta que nombre la capacidad que el candidato aporta, ej. "Aporta control
  que el equipo no tiene todavía".

## Reglas duras
- Función pura, sin I/O, nunca lanza para entradas válidas.
- `raw: null` solo si el equipo propio no tiene ningún pick todavía Y no hay forma de evaluar
  huecos (define explícitamente ese caso borde en la prueba — no lo dejes implícito).
- Nunca inventar datos de sinergia medida — es explícitamente una heurística sobre `roles[]`, no
  una consulta a una fuente de winrate conjunto.

## Aceptación
- Prueba con equipo propio vacío → comportamiento explícito y documentado (raw numérico neutro
  justificado, o `raw: null` — decidir y dejar la prueba como documentación del criterio).
- Prueba con equipo propio que ya cubre control/iniciación → un candidato que aporta esas mismas
  capacidades puntúa más bajo que uno que aporta una capacidad faltante.
- `sampleSize` es `0` en todos los casos.
