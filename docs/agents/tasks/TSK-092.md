## Contexto/Problema

Sesión explícita de "Governance 2.0" pedida por el usuario. `scripts/verify-simplicity.sh`
bloqueaba commits por `MAX_FILES=3`/`MAX_LINES=200`/`MAX_TEST_LINES=350` -- el propio script ya
documentaba (comentario de `MAX_TEST_LINES`) que exactamente este cambio (bajar esos tres checks
de bloqueo a aviso) se había intentado una vez en TSK-067 y se revirtió como hallazgo real, no
cosmético. Antes de tocar el archivo se confirmó con el usuario vía pregunta directa
(`AskUserQuestion`, ver plan de esta sesión) si esta vez la anulación era deliberada -- respuesta
explícita: sí, anular TSK-067 a propósito. Esta es la diferencia real entre esta sesión y TSK-067:
una decisión confirmada, no un cambio silencioso de otra herramienta.

Al mismo tiempo, el working tree tenía ~82 archivos pendientes de sesiones previas (21 tickets
`TSK-068`-`TSK-088`, todos ya `state: done`, nunca comiteados) que había que organizar en commits
lógicos sin descartar nada.

## Archivos impactados

- `scripts/verify-simplicity.sh` -- `FILES_TOUCHED`/`PROD_LINES_ADDED`/`TEST_LINES_ADDED` dejan de
  sumar a `$ERRORS` (siempre `⚠️`, nunca bloquean); se elimina la lectura de
  `simplicity_exception` del ticket para esos tres checks (queda muerta). El check de
  dependencias (sección 3) distingue ahora la clave exacta del `package.json` -- solo
  `dependencies` (producción) exige `// ALLOWED`, `devDependencies` tiene bypass total. Sección
  nueva (8): compilación (`tsc --noEmit`, `apps/engine` y `apps/web`) + suite de tests (`bun
  test`, ambas apps) como hard gate real, sin excepción posible, activado solo cuando
  `VERIFY_COMMIT_GATE=1` -- para no cargar los hooks `PostToolUse`/`SubagentStop` (que corren este
  mismo script en caliente tras cada `Edit`/`Write`) con una suite completa por cada edición.
  Resolución de binario de `bun` agnóstica al entorno (`BUN_BIN`): en esta máquina `bun` no
  resuelve en el `$PATH` del hook pero `bunx` (symlink a `~/.bun/bin/bun`) sí -- sin esto el gate
  fallaba por "command not found", no por una razón real.
- `scripts/hooks/pretooluse-guard.sh` -- exporta `VERIFY_COMMIT_GATE=1` al invocar el script en
  `git commit`/`push`. Se retira la extracción de `COMMIT_TICKET` (quedó sin ningún consumidor en
  el script tras el punto anterior).
- `CLAUDE.md` / `.claude/rules/security.md` -- política de dependencias por categoría:
  `dependencies` de producción sigue exigiendo `/gear-up`/`@depcheck`; `devDependencies` de
  tooling de infraestructura rutinaria del stack Bun tiene bypass total.
- `apps/engine/package.json` -- `typescript` como `devDependency` nueva (bypass, primer caso real
  de la política nueva), necesaria para que el gate de tipos pueda correr sobre `apps/engine`
  (antes no tenía `tsc` disponible, solo transpilación de Bun).
- 9 archivos de fixtures de test (`counter.test.ts`, `hero-pool-fit.test.ts`, `mix.test.ts`,
  `patch-meta.test.ts`, `position-fit.test.ts`, `team-synergy.test.ts`, `build-paths.test.ts`,
  `gaps.test.ts`, `batch-harness.ts`) -- hallazgo real del nuevo gate de tipos: el `DraftState` de
  TSK-072 agregó 3 campos requeridos (`firstPickSide`/`turnStartedAt`/`reserveRemainingMs`) que
  varios fixtures del motor, escritos antes de esa fase, nunca incorporaron. `tsc --noEmit` no
  compilaba sobre el estado real del repo hasta corregirlos -- no es alcance nuevo de esta sesión,
  es deuda pre-existente que el gate nuevo hizo visible por primera vez.

## Resultado

`VERIFY_COMMIT_GATE=1 bash scripts/verify-simplicity.sh`: verde (tipos + 408/408 tests de
`apps/engine`, 133/133 de `apps/web`). Verificado con casos sintéticos que `devDependencies` no
dispara error y `dependencies` sin `// ALLOWED` sí sigue bloqueando. Working tree consolidado en
commits lógicos por dominio (ver `journal.md`, entradas de esta misma sesión).

## Verificación

`bash scripts/verify-simplicity.sh` (camino rápido, sin `VERIFY_COMMIT_GATE`) sigue corriendo sin
`tsc`/`bun test` -- confirmado con `grep` sobre la salida. Commit/push real vía
`pretooluse-guard.sh` corre el gate completo -- confirmado leyendo el hook actualizado.
