## Contexto

SPEC.md §16.6, costura S18. `SignalContribution` gana dos campos aditivos y el motor gana el loader
de la calibración empírica. El contrato `SignalScorer.score()` **no cambia de firma**.

## Alcance

1. **`apps/engine/src/signals/types.ts`** — `SignalContribution` gana:
   - `normalized: number | null` — `raw` calibrado a `[0,100]`, o `null` si `raw` es `null`.
   - `evidenceConfidence: number` — `[0,1]`, cuánta evidencia respalda ese `raw`.
   Ningún campo actual se borra. `SignalScorer` no cambia.
2. **`apps/engine/src/signals/calibration.ts`** (nuevo):
   - `loadCalibration(): Calibration` — lee `data/generated/percentiles.json`, valida en el borde
     (esquema, `p05 < p95`, no NaN, `SignalId` conocido). Archivo corrupto / ausente / forma
     inesperada → devuelve una `Calibration` "vacía" que hace que `normalize()` caiga a
     `RAW_RANGE`. **Nunca lanza.** Mismo criterio literal que `loadHeroPositions()`.
   - `calibratedNormalize(signal, raw, bracket, calibration): number` —
     `clamp((raw − p05)/(p95 − p05), 0, 1) * 100`, con `p05`/`p95` de `byBracket[bracket]` si
     existe, si no `global`, si no (sin calibración para esa señal) `RAW_RANGE[signal]`.
   - `enrich(contribution, bracket, calibration): SignalContribution` — agrega `normalized`
     (`raw === null ? null : calibratedNormalize(...)`) y `evidenceConfidence` (§16.6:
     estadísticas → `raw === null ? 0 : sampleSize/(sampleSize + K)` con `K_position_fit=200`,
     `K_counter=20`, `K_patch_meta=200`; categóricas → `raw === null ? 0 : 1`).
   - `MODULE_CALIBRATION = loadCalibration()` a nivel de módulo. Inyectable vía parámetro para
     tests (patrón `heroPositions?`/`heroCounters?`).
3. Los scorers **no se tocan** — siguen devolviendo `raw`/`weighted:0`/`explanation`/`sampleSize`
   (sin `normalized`/`evidenceConfidence`). El campo se agrega en `mix.ts` vía `enrich()` (TSK-210).
   Para que `apps/engine` compile con `SignalContribution` ampliada, `normalized`/`evidenceConfidence`
   se agregan como **requeridos** y cada `return` de scorer que hoy no los pone se ajusta con
   `normalized: null, evidenceConfidence: 0` — o `SignalContribution` los declara opcionales y
   `enrich()` los rellena. **Decisión del ticket, documentada**: opcionales para no tocar 6
   scorers; `mix.ts` garantiza que salgan siempre poblados hacia la UI.

## Criterios de aceptación

1. `calibration.test.ts`: `loadCalibration()` con fixture válido → `calibratedNormalize` usa
   `byBracket` cuando existe, `global` si no, `RAW_RANGE` si la señal no está calibrada.
2. `loadCalibration()` con JSON corrupto / archivo ausente / `p05 > p95` → `Calibration` vacía,
   `calibratedNormalize` == `normalize` de `RAW_RANGE`, **cero excepción**.
3. `enrich()`: `raw: null` → `normalized: null`, `evidenceConfidence: 0`. `raw` numérico con
   `sampleSize` grande → `evidenceConfidence` cerca de 1; con `sampleSize` chico → bajo.
4. `bunx tsc --noEmit` limpio en `apps/engine`. `bun test apps/engine` verde.
5. `git diff --name-only`: sólo `apps/engine/src/signals/{calibration.ts,calibration.test.ts,types.ts}`.
   **`weights.ts`/`mix.ts` NO aparecen** en este ticket.
