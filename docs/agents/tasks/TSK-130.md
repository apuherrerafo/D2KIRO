## Alcance — 1 archivo (+ su test)

**`apps/engine/src/pipeline/feature-extractor.ts`**: `extractCandidateFeatures` conserva firma y
tipo de retorno exactos (cero regresión, sus pruebas actuales no se tocan). Gana un segundo export:

```ts
import { openingStrategy } from "../draft-paths/strategy";
import type { DraftPathArchetype, HeroCapabilities } from "../draft-paths/types";

export function extractCandidateStrategies(
  candidates: readonly HeroId[],
  capabilities: readonly HeroCapabilities[],
): Map<HeroId, DraftPathArchetype>;
```

Reglas exactas:
- Devuelve **una entrada por candidato, siempre** — nunca omite héroes (a diferencia de
  `extractCandidateFeatures`, que descarta a los sin perfil de línea). Un héroe sin entrada en
  `capabilities.json` recibe `"scaling"` — mismo default que `openingStrategy` ya devuelve hoy.
- **No filtra por `state`** — la exclusión de baneados/pickeados ya la hizo quien construyó
  `candidates`. Duplicar el filtro sería una segunda copia de `candidatePool`.
- `capabilities` es **obligatorio**, nunca opcional con default que cargue el archivo real (mismo
  criterio que `buildMetaSnapshot(db, accountId)` en `engine.md` — un default silencioso repetiría
  ese tipo de bug). La inyección del archivo real ocurre una sola vez, en la ruta (TSK-133).

## Costura (S9, `testing-seams.md`)

## Criterios de aceptación

- Con `capabilities = []`, todos los candidatos reciben `"scaling"`.
- Con un candidato ausente del array `capabilities`, recibe `"scaling"` (no lanza, no lo omite).
- Devuelve exactamente `candidates.length` entradas — nunca más, nunca menos.
- `extractCandidateFeatures` sigue pasando sus pruebas actuales sin ninguna expectativa cambiada.
