## Contexto

SPEC.md §15.4.3, §15.9. Un solo comando corre ambos benchmarks y emite el artefacto congelado que
9.1→9.5 tendrán que superar.

## Alcance

1. **`scripts/eval/run.ts`** + entrada `"eval": "bun run scripts/eval/run.ts"` en `package.json`.
2. Corre Benchmark A (TSK-201) y B (TSK-200), junta:
   - `eval/baselines/v6-measured.json` — Benchmark A + B + los 5 baselines + toda la segmentación
     (`decisionContext` × `tier` para B, `decisionContext` × `strata` para A), + metadata:
     `generatedAt`, `commit` (SHA de `git rev-parse HEAD`), `splitHash`, `corpusSize`,
     `snapshotSyncedAt`. **El `commit` es obligatorio** — un baseline sin commit identificable no es
     un baseline (§15.11).
   - `eval/reports/<timestamp>.md` — versión legible para humanos, con la advertencia de ADR-002
     ("comparativo, no predictivo") impresa arriba.
3. **Determinismo**: dos corridas seguidas (mismo commit, mismo split, mismo snapshot) → el
   `v6-measured.json` es **byte-idéntico**. `eval/reports/` va a `.gitignore`; `eval/baselines/` se
   versiona.
4. Si el gate `ConstraintViolationRate` de cualquiera de los dos benchmarks falla → `run.ts` sale
   con código ≠ 0 y **no escribe** `v6-measured.json`.

## Criterios de aceptación

1. `bun run eval` sobre fixtures produce `v6-measured.json` + un reporte `.md`.
2. `v6-measured.json` incluye `commit`, `splitHash`, `snapshotSyncedAt` y la segmentación completa.
3. Dos corridas consecutivas → `diff` vacío en `v6-measured.json`.
4. Fixture que dispara `ConstraintViolationRate > 0` → exit ≠ 0, no se escribe el baseline.
5. `.gitignore` ignora `eval/reports/`. `git diff --name-only` no toca `apps/`.
6. `verify-simplicity.sh` verde.
