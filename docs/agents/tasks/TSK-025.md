## Reglas duras
- **Nunca auto-aplicar la propuesta.** El `PUT` solo se dispara por una acción explícita del
  usuario ("confirmar" o "guardar tras editar").
- Convenciones de `.claude/rules/web.md`: sin `any`, sin ternarios para renderizado condicional,
  sin funciones anónimas inline, tokens de diseño semánticos.
- Error boundary y estado de carga propios de esta feature.
- Cada héroe propuesto se muestra con su ícono oficial.
- RTK Query para las llamadas HTTP — no WebSocket, esto no es la vista de draft en vivo.

## Aceptación
- Con un `account_id` válido y un mock/fixture con héroes reales, la pantalla muestra hasta 5
  propuestos con winrate/partidas visibles.
- "Descartar" no modifica el pool guardado — verificable con un `GET /api/hero-pool` antes y
  después, sin diferencia.
- "Confirmar tal cual" deja el pool guardado exactamente igual a la propuesta.
- Con `proposed: []`, se muestra el mensaje de "ningún héroe pasa el mínimo", no una lista vacía
  muda ni un error.
- Con `502 opendota_unavailable`, el mensaje deja claro que el pool existente (si hay) sigue
  funcionando — no genera pánico de "se rompió todo".
