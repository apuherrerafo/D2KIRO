## Contexto

SPEC.md §15.4.4, costura S17. Carga y valida los casos etiquetados a mano. **Un caso malformado se
descarta con motivo; el archivo entero nunca tira el runner** — mismo criterio literal que
`loadHeroPositions()` / `loadHeroCounters()`.

## Alcance

Esquema (`data/schemas/golden.schema.json` + tipo en `golden.ts`):

```
{ schemaVersion: 1,
  cases: [{
    id: string,
    source: {kind:"replay", matchId:string, turnIndex:number} | {kind:"synthetic", note:string},
    state: DraftState, side: "radiant"|"dire", decisionContext: DraftDecisionContext,
    strata: string[],   // "hard_counter"|"flexibility"|"role_scarcity"|"team_needs"
                        // |"composition"|"punishability"|"historical_failure"
    labels: { excellent:[{hero:HeroId, why:string}], acceptable:[...], bad:[...] },
    reasoningTags: string[], labeledAt: string, labeledBy: string
  }] }
```

`loadGoldenDataset(raw: unknown): { cases: GoldenCase[]; rejected: {id?:string, reason:string}[] }`:

- Descarta el **caso** (no el archivo) si: héroe desconocido (contra el catálogo de 127), un mismo
  héroe en dos de las tres listas, `state` que no pasa el type-guard de `DraftState`, `excellent`
  vacío, `strata` vacío, `id` duplicado.
- Raíz ausente, JSON inválido o `schemaVersion` desconocida → `{ cases: [], rejected: [...] }`,
  **nunca lanza**.
- `eval/golden/README.md`: cómo se etiqueta un caso (multi-label, `why` obligatorio por héroe,
  `reasoningTags`), y que el archivo se cura por parche → **ninguna prueba puede leerlo real**.

## Criterios de aceptación

1. Fixture inline con 1 caso válido + 1 con héroe desconocido + 1 con héroe en dos listas + 1 con
   `excellent` vacío → `cases.length === 1`, `rejected.length === 3`, cada uno con motivo legible.
2. `raw = "{"` (JSON roto) → `{cases:[], rejected:[{reason:...}]}`, sin excepción.
3. `raw = {schemaVersion: 99, cases: []}` → rechazado por versión, sin excepción.
4. `bunx tsc --noEmit` limpio. **Ninguna prueba lee `eval/golden/*.json` real.**

El runner que consume los casos (TSK-201). La herramienta de propuesta (TSK-204).
