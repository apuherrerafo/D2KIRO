## Contexto
Depende de TSK-004 (contrato de eventos), TSK-010 (`POST /api/session/manual`) y TSK-012 (vista
de draft, estado `esperando_draft`/`degradado`). Marcado Must-have: junto al simulador, `manual`
es el único capturador de primera clase disponible en fase 1 (Overwolf/OCR quedan para después),
por lo que es la única forma de validar el criterio de aceptación 1 del SPEC ("luego se repite
contra una partida real") sin depender de una incógnita aún no resuelta.

## Qué construir
- UI para que el usuario marque picks/bans manualmente cuando la detección automática falla o no
  existe — usa el mismo `POST /api/session/manual` (mismo `DraftEventEnvelope`,
  `source: 'manual'`, `confidence: 1.0`).
- Camino de degradación en la UI: cuando `capture_health: 'lost'` llega por WebSocket, se muestra
  el aviso correspondiente **y se habilita la entrada manual sin perder el estado ya capturado** —
  el draft parcial capturado hasta ese punto sigue visible y editable.
- Confianza por debajo de `0.6` (de cualquier capturador, no solo manual): el estado queda
  marcado como "sin confirmar" en la UI, con una acción táctil para corregir (usa
  `pick_reverted` del contrato de TSK-004 para deshacer un error).

## Reglas duras
- La entrada manual nunca reinicia la sesión — se integra al mismo `DraftState` ya existente.
- Un héroe no reconocido nunca se inventa como `HeroId` — si el usuario no encuentra el héroe en
  la lista (por ejemplo, uno nuevo tras un parche todavía no sincronizado), la UI lo comunica
  explícitamente en vez de aceptar un id inválido.

## Aceptación
- Con el estado `capture_health: 'lost'` simulado (vía el simulador de TSK-011 o un fixture), la
  UI habilita la entrada manual y conserva todo el draft capturado hasta ese punto.
- Marcar un pick manualmente produce el mismo efecto en `DraftState` que si lo hubiera reportado
  el simulador.
- Un evento con confianza <0.6 se muestra como "sin confirmar" y puede corregirse sin perder el
  resto del draft.
