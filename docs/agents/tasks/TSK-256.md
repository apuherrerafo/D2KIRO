## Contexto

Hallazgo demostrado por Codex en la revisión de `AGENT_ARCHITECTURE_REVIEW_BLOCKED` (HEAD `98c903e8`):
`claude_doing_tickets` (`scripts/hooks/_hook_lib.py`) salta todo ticket cuyo `assigned_tool` no sea `""` ni
`claude-code`. `assigned_tool: null` (valor que el propio sistema escribe para "sin asignar") cae en ese salto,
así que el ticket en `doing` deja de gobernar a la sesión y `write-scope-guard` permite escribir fuera de
`write_scope` (fail-open). `verify-simplicity.sh` y `hub.ts` sí tratan `null` como `claude-code`: tres
intérpretes, dos criterios.

## Regla

Sólo un ticket con `assigned_tool` EXACTAMENTE `codex`, `kiro-nativo` o `hermes-vps` (tras quitar espacios y un par
de comillas que cierra) deja de gobernar a Claude Code. Todo lo demás — ausente, vacío, `null`, desconocido,
malformado, otra capitalización, clave duplicada — gobierna a Claude Code. Se lee sólo del frontmatter, nunca del
cuerpo. Hook, `verify-simplicity.sh` y `hub.ts` aplican la misma regla (incluido CRLF).
