sobre el pick profesional. Titular **NDCG@5**.

## Alcance

- `benchmark-engine-quality.ts`: carga los casos vía `loadGoldenDataset` (TSK-199), corre
  `buildSuggestions` (V6) sobre cada `state`, calcula por caso: **NDCG@5** (ganancia
  `excellent=2/acceptable=1/bad=0`), **Bad Pick Rate@5** (héroe no etiquetado = desconocido, se
  excluye), **Pairwise Accuracy**.
- Agrega: media + IC bootstrap (resamplea casos), **segmentado por `decisionContext` y por
  `strata`**.
- Corre también los 5 baselines de `baselines.ts` (TSK-200) sobre el mismo Golden Dataset.
- Salida: objeto estructurado para el orquestador (TSK-202).
- Mismo gate `ConstraintViolationRate = 0` que TSK-200.

## Criterios de aceptación

1. Test con un Golden Dataset **fixture inline** de ~5 casos (uno por `decisionContext` + un par de
   estratos): NDCG@5, Bad Pick Rate@5 y Pairwise aparecen por caso y agregados, segmentados.
2. Un caso con 3 `excellent` y el ranking los pone 1-2-3 → NDCG@5 alto (test fija cota).
3. Un caso donde V6 pone un `bad` en el top-1 → Bad Pick Rate@5 ≥ 0.2 y se ve en el segmento.
4. **Ninguna prueba lee `eval/golden/` real.** `git diff --name-only` no toca `apps/`.
5. Determinismo byte a byte entre corridas.
