## Contexto

`r1-certification (verify:r1)` es un contexto REQUERIDO y tiene `needs: [test, verify-simplicity, intelligence-ci]`. `test (qa)` es una pata de la
matriz `test` y NO es requerido por sí solo. Si cualquier `needs` falla, GitHub omite (`skipped`) el job, y un check requerido omitido no bloquea la fusión.

## Estado

- **Implementado:** `if: ${{ !cancelled() }}` + primer paso que sale con 1 si algún `needs.*.result` no es `success` (los resultados llegan por `env`, no se interpolan en el script). Con eso un `test (qa)` en rojo produce un FALLO del check requerido.
- **Funciona:** rojo→verde con `scripts/ci/ci-needs-semantics.test.ts` (simula la semántica de `needs` sobre el ci.yml real y EJECUTA el paso guardia con bash): antes 3 pass / 6 fail; después 9 pass / 0 fail; tras la revisión de Codex (orden del guardia, `!cancelled()`) 11 pass. Incluye el caso sin falso positivo (todo en success).
- **Pendiente:** NOT_TESTED en GitHub real (haría falta un PR de prueba con `qa/` roto: requiere push). `actionlint` no instalado. El paso "Upload certification report" (`if: always()`) correrá sin reporte tras un fallo del guardia: sólo avisa. `ci.yml` es ruta crítica: exige revisor externo antes de fusionar.
