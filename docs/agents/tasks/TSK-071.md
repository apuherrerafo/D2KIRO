## Contexto/Problema

QA manual en vivo de `/draft` (misma sesión donde se cerraron TSK-068/069/070) reveló que la
vista se siente como "un panel de control estático", no como un draft real de Dota. Uno de los 3
frentes del rediseño (`/dispatch` → `/grill-me`, 2026-08-23): timer + indicador de turno con la
lógica real de Dota, confirmado explícitamente por el usuario ("tal cual, misma lógica de picks y
timing", no una versión simplificada) y, en la entrevista de convergencia, con las 3 decisiones
más exigentes de las ofrecidas: **ambos formatos** (Captain's Mode y All Pick), **validación
dura** (el motor rechaza un pick/ban fuera de turno) y **sistema de reserva real** (banked time,
no un contador fijo por turno).

Hoy `DraftState` (`apps/engine/src/draft/reducer.ts`) no tiene ningún concepto de turno ni de
reloj — es deliberado, no un olvido: `.claude/rules/engine.md` prohíbe modelar la tabla de turnos
de Valve como lógica adivinada del reductor, exige que viva como **dato curado**, mismo patrón que
`hero-positions.json` (Fase 3) y `capabilities.json` (Fase 2). Esta tarea es exactamente eso: el
dato, no la lógica que lo consume (eso es TSK-072).

**Importante — no inventar los números de memoria.** El sistema de tiempo de reserva
("banked time") de Captain's Mode competitivo, y el esquema de tiempo de All Pick con bans en
matchmaking actual, cambiaron entre parches y entre reglamentos de torneo. Antes de curar el
archivo final, verificar los valores reales (tiempo base por selección, tamaño del banco de
reserva por equipo, cuántos bans tiene All Pick en el parche `7.41e` — el `CLAUDE.md` de Fase 1b
ya menciona "guion de bans de allPick ampliado a 16" como contenido de guion, no como dato
verificado de reglas oficiales) contra una fuente autoritativa actual (Dota 2 Wiki / reglas
oficiales de Valve), con el mismo rigor de sourcing documentado que usó `hero-positions.json`
(TSK-043, método de scraping anotado a mano en el archivo).

## Alcance

- Nuevo archivo `apps/engine/src/draft/draft-format-turns.json`: por cada `DraftFormatId`
  (`all_pick`, `captains_mode`), la secuencia ordenada de turnos (`side: TeamSide | "either"`,
  `action: "ban" | "pick"`), el tiempo base por turno (segundos) y el tamaño del banco de reserva
  por equipo (segundos).
- Loader `apps/engine/src/draft/draft-format-turns.ts`: valida el archivo al cargar (mismo
  criterio que `loadHeroPositions()` — secuencia vacía/turno malformado/tiempo negativo degrada a
  "sin datos de turno para este formato", nunca tira el motor). Exporta el tipo
  `DraftFormatTurnTable`.
- `format: 'unknown'` (estado legítimo, engine.md) **no tiene entrada** en la tabla — el loader
  debe devolver explícitamente "sin tabla de turnos" para ese caso, nunca un array vacío
  interpretado como "todos los turnos ya jugados".

## Criterios de aceptación

1. Los tiempos base y de reserva de ambos formatos están verificados contra una fuente actual, no
   copiados de memoria — la fuente exacta queda anotada en un comentario en el JSON o el loader,
   mismo criterio que `hero-positions.json`.
2. `format: 'unknown'` nunca produce un turno inventado.
3. Un archivo corrupto degrada a "sin datos de turno", nunca lanza una excepción que tire el motor
   (prueba unitaria obligatoria, mismo patrón que `parseHeroPositions`).
4. Prueba unitaria que verifica que la secuencia curada de cada formato tiene una cantidad de
   turnos consistente con lo que el reductor ya acepta hoy (ban/pick reales observables en
   `simulator-scripts.ts` como referencia cruzada, no como fuente de verdad).

## Resultado

Dato curado con investigación real del usuario (documento cruzado contra Liquipedia/Valve,
23/08/2026) -- no aproximado. `draft-format-turns.json`: Captain's Mode completo (24 turnos, 14
bans + 10 picks, 6 fases con notación relativa `first`/`second` -- ver Alcance para por qué no es
`radiant`/`dire` directo --, 15s primera fase de bans, 30s el resto, 130s de reserva por equipo).
All Pick: `banCount: 16` + `banSource: "player_ban_preferences"` (el algoritmo interno exacto que
Valve usa para convertir preferencias en los 16 bans finales NO está documentado públicamente --
se guarda la fuente conocida, nunca se inventa el algoritmo) + `pickRounds` (2/2/1, 25s/25s/20s).

**Hallazgo que redefine el alcance de TSK-072, confirmado por la investigación del usuario**:
Ranked All Pick NO es "A → B → A → B" -- los picks de cada ronda son simultáneos y ocultos hasta
un reveal conjunto, con lógica de conflicto si ambos equipos eligen el mismo héroe. Es un
mecanismo estructuralmente distinto de `wrong_turn` (que asume una secuencia estrictamente
alternada, un solo lado activo por turno) -- construir el sistema real de rondas ocultas
necesitaría un concepto de "pick pendiente sin revelar" que hoy no existe en ningún lado del wire,
es una feature aparte, más grande. `pickRounds` queda curado como dato de referencia (útil para
UI/timers futuros), pero TSK-072 no lo usa para `wrong_turn`.

`draft-format-turns.ts`: loader con el mismo criterio de validación que `hero-positions.ts` --
`captainsMode`/`allPick` se validan por separado (uno corrupto no tira al otro), cualquier turno
malformado degrada la tabla completa a `null`, nunca lanza.
