## Contexto

Verificación independiente del reporte de Codex sobre la corrección de transición de rondas
(TSK-112, ya commiteado) encontró una regresión real en el árbol de trabajo sin commitear:
`apps/web/features/random-draft-simulator/__tests__/store.test.ts` tenía dos pruebas nuevas que
referenciaban `previewStatus`/`setPreviewStatus`, una API que nunca se implementó en `store.ts`.
El reporte de Codex decía "suite web completa: 177 tests, 0 fallos" -- al correr `bun test` el
árbol real tenía 178 pruebas con **2 fallos**. Corresponde al punto 1 de los 5 que el propio Codex
identificó como siguiente endurecimiento ("Convertir Copilot en una máquina explícita: cargando,
listo, falló con reintento; jamás 'actualizando' infinito").

Hallazgo adicional confirmado en el código antes de esta prueba: `refreshPendingPickPreview`
(`use-random-draft-session.ts`) atrapaba el error de fetch en silencio y dejaba `suggestions` en
`null` para siempre -- exactamente el "actualizando infinito" que describía el reporte.

## Cambios

- `store.ts`: nuevo campo `previewStatus: "idle" | "loading" | "ready" | "failed"` +
  `setPreviewStatus`. Se resetea a `"idle"` en `startSession`/`resetSession`.
- `use-random-draft-session.ts`: `refreshPendingPickPreview` marca `"loading"` antes del fetch,
  `"ready"` cuando aplica la respuesta fresca, `"failed"` en `!response.ok` o excepción -- solo si
  la petición sigue siendo la vigente (mismo guard `matchesPreviewState`/pending picks que ya
  usaba el código). Nuevo `retryPreview()` expuesto en `actions`, que repite el pedido de la ronda
  vigente sin esperar un cambio de estado.
- `CopilotPanel.tsx`: `UpdatingNotice` (binaria) reemplazada por `PreviewStatusNotice` (3 estados):
  `"failed"` muestra el error con botón "Reintentar"; `"loading"` o sin sugerencias frescas
  muestra "Calculando recomendación..."; `"ready"` no agrega texto propio.
- `app/simulator/page.tsx`: pasa `previewStatus`/`onRetryPreview` reales al `CopilotPanel`.

## Verificación

- `bun test` (apps/web): 178 pass, 0 fail (antes: 176 pass, 2 fail -- confirmado en este ticket,
  no solo prometido).
- `bunx tsc --noEmit` (apps/web): limpio.
- `bun test` (apps/engine): 471 pass, 0 fail -- sin tocar, confirma que el motor no se vio
  afectado por este cambio (100% frontend).
