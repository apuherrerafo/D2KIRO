## Diseño acordado (ronda 2, aprobado)

### Cálculo bajo demanda, no por WebSocket
`draft_paths` NUNCA se empuja automático por evento de draft (a diferencia de `suggestions`) --
la regla dura de `engine.md` ("draft_state antes que suggestions, siempre") queda intacta sin
modificar. Se calcula vía `GET /api/session/:sessionId/draft-paths`, leyendo el `DraftState` en
memoria del `SessionStore` existente, solo cuando el usuario abre el panel en el cliente.

### Hueco de datos: `capabilities.json` curado
`apps/engine/src/draft-paths/capabilities.json` -- archivo estático versionado, NO en SQLite
(dato de producto curado, no meta remota ni preferencia de usuario). Shape:
```ts
type CapabilityLevel = "low" | "medium" | "high";
type DamageType = "physical" | "magical" | "pure" | "mixed";
interface HeroCapabilities {
  hero: HeroId;
  damageType: DamageType;
  hasInitiation: boolean;
  hasCatch: boolean;
  hasWaveclear: boolean;
  structuralDamage: CapabilityLevel;
  teamfight: CapabilityLevel;
  scaling: CapabilityLevel;
}
```
Héroes sin entrada: no participan como `nextPick` ni `followUp`, nunca rompen el cálculo (mismo
espíritu que `applicable: false` en el resto del motor -- "sin dato", no "malo"). **Primer
borrador generado por Codex con su mejor criterio del juego -- tratado explícitamente como
revisable, el usuario lo corrige a mano antes de considerarlo confiable, no es verdad final.**

### Interfaz -- capa paralela, nunca mezclada con el motor de sugerencias existente
```ts
type DraftPathArchetype = "push" | "teamfight" | "pickoff" | "scaling";
type DraftCapabilityGap = "initiation" | "catch" | "waveclear" | "structural_damage" | "teamfight" | "scaling" | "damage_mix";
interface DraftPathStep { hero: HeroId; score: number; fills: DraftCapabilityGap[]; reasons: string[]; }
interface DraftPath { archetype: DraftPathArchetype; label: string; score: number; missing: DraftCapabilityGap[]; nextPick: DraftPathStep; followUps: DraftPathStep[]; reason: string; }
interface DraftPathSet { schema: "draft-paths/v1"; sessionId: string; basedOnSeq: number; paths: DraftPath[]; computedInMs: number; }
```
No es `SignalContribution`. No toca `SCORING_WEIGHTS_V1/V2/V3`. No afecta `SuggestionSet` ni el
ranking de `buildSuggestions` -- decisión explícita: por ahora es puramente exploración aparte,
nunca cambia el pick #1 sugerido.

### Umbrales exactos (gaps del draft propio)
`LEVEL_SCORE = { low: 0, medium: 1, high: 2 }`. Usando solo héroes propios con `capabilities`
conocidas:
- `initiation`/`catch`/`waveclear`: gap si `ownHeroesWith(flag) === 0`.
- `structural_damage`/`teamfight`/`scaling`: gap si `sum(LEVEL_SCORE[...]) < 2`.
- `damage_mix`: gap si `knownDamageTypes.length >= 2` Y todos los héroes conocidos no-"mixed"
  comparten el mismo `damageType` Y ningún héroe es `damageType: "mixed"` -- con menos de 2
  héroes con dato conocido, nunca se marca (evita sobrediagnosticar en el pick 1).

### Scoring por arquetipo
Prioridades fijas por arquetipo (push: structural_damage=3/waveclear=2/catch=1; teamfight:
initiation=3/teamfight=3/damage_mix=1; pickoff: catch=3/initiation=2; scaling: scaling=3/
waveclear=1/damage_mix=1) + `archetypeFitBonus` (high=+2/medium=+1 según la métrica del propio
arquetipo, o hasCatch=+2/hasInitiation=+1 para pickoff). Un arquetipo solo aparece si
`nextPick.score >= 3`. `followUps`: siguientes 2 mejores del mismo arquetipo, excluyendo
`nextPick` -- puede ser 0. Máximo 3 caminos, ordenados por score descendente. Candidatos excluyen
baneados, ya elegidos (ambos lados), y héroes sin `capabilities`. Nunca predice al rival.

### UI
`apps/web/features/draft-paths/` (patrón de feature estándar) + `apps/web/components/
draft-path-card/DraftPathCard.tsx`. Panel "Caminos de draft" **cerrado por defecto**, con botón
para abrirlo -- consistente con el cálculo bajo demanda (nunca se dispara la consulta si el
usuario no lo pide). Cover-flow navegable, hasta 3 tarjetas. Texto: "Le falta al draft", "Win
condition", "Prioridades del equipo" -- nunca "needs-based drafting" (no es el término real que
usa la comunidad, confirmado por la investigación).

## Fuera de alcance
- Ejes de timing (early/mid/late) y forma de recurso (four-protect-one, multi-core) -- iteración
  futura.
- Condición de victoria primaria + secundaria combinada -- iteración futura.
- Cualquier predicción o consideración del draft del equipo rival.
- Que el camino elegido por el usuario afecte `buildSuggestions` -- decisión explícita de no
  mezclarlos en esta fase.

## Aceptación
- `capabilities.json` con entradas parciales (no bloquea por completar los ~126 héroes).
- `GET /api/session/:id/draft-paths` nunca se dispara automático -- solo cuando el cliente lo pide.
- `draft_state`/`suggestions` siguen empujándose por WebSocket exactamente igual que antes --
  regresión cero, verificable porque ningún test existente de esa regla se toca.
- Con un draft sin ningún héroe propio con `hasInitiation`, el arquetipo `teamfight` debe
  considerar `initiation` como gap real (verificable con números exactos, no aproximados).
- `damage_mix` nunca se marca como gap con menos de 2 héroes propios con `capabilities` conocidas.
- Ningún camino aparece si su `nextPick.score < 3`.
