## Contexto

El QA de `TSK-212` mostró que 9.1 completo regresiona NDCG@5 (0.687 → 0.566). La ablación
(`scratchpad/ablate.ts`) aisló la causa:

| Configuración | NDCG@5 | BadPick@5 | Pairwise |
|---|---|---|---|
| V6 puro (`_legacyMixMode`) | 0.687 | 28.5% | 55.5% |
| **per-state + RAW_RANGE (calibración apagada)** | **0.736** | **26.0%** | **61.9%** |
| per-state + calibración empírica (9.1 actual) | 0.566 | 24.7% | 51.1% |
| per-state + calib, sin `patch_meta` | 0.648 | 23.2% | 56.1% |

La **mezcla por estado es un acierto** (cumple E9 en los 2 ejes). La **calibración empírica de
`TSK-208` resta** — los percentiles del corpus pro son demasiado angostos y saturan las señales.
Ni la mejor variante de calibración llega a lo que da per-state solo.

Decisión (lead architect, `journal.md` evt-20260830-242): dejar per-state activo, calibración
empírica queda **opt-in** (`options.calibration`) e infra latente para 9.3 (gating contextual con
percentiles por contexto). El rulebook de 9.1 ya lo previó (E9: "si la calibración no lo logra,
9.1 igual entra… la palanca real está en 9.3").

## Alcance

1. **`calibration.ts`**: `export const EMPTY_CALIBRATION` (ya existe como const interna — sólo se
   exporta). `MODULE_CALIBRATION` se conserva exportado (opt-in / 9.3).
2. **`mix.ts`**: el default del camino activo pasa de `options.calibration ?? MODULE_CALIBRATION`
   a `options.calibration ?? EMPTY_CALIBRATION` → `calibratedNormalize` cae a `RAW_RANGE`. Comentario
   con el hallazgo del QA. `enrich()`/`normalized`/`evidenceConfidence`/`EvidenceCoverage` sin
   cambios (son de per-state). `_legacyMixMode` sin cambios.
3. **`mix.test.ts`**: prueba nueva — `buildSuggestions` sin `options.calibration` normaliza con
   `RAW_RANGE` (un `normalized` concreto lo demuestra), no con percentiles. Los candados de
   regresión cero y sensibilidad siguen verdes.
4. **Re-congelar `eval/baselines/v6-measured.json`**: `bun run scripts/eval/run.ts` con el motor
   ya en per-state + RAW_RANGE → nuevo baseline de referencia "9.1-medido" para 9.2+. El pre-9.1
   (V6, `ab09ca6`) queda en git history.
5. **ADR-004 addendum**: la calibración empírica se midió net-negativa en Engine Quality; se
   difiere a 9.3 con percentiles por contexto. Per-state se queda.

## Criterios de aceptación

1. `bun run scripts/eval/gate.ts --enforce` contra el baseline pre-9.1 → **PASS** antes de
   re-congelar; tras re-congelar, `current == baseline` → PASS trivial.
2. NDCG@5 de `v6Full` en el nuevo `v6-measured.json` ≥ 0.72 (per-state solo, medido 0.736);
   BadPick@5 ≤ 0.27.
3. `bunx tsc --noEmit` limpio en `apps/engine`. `bun test apps/engine` verde. Candados de
   regresión cero de `mix.test.ts` intactos.
4. `git diff --name-only`: sólo los archivos del `write_scope`. `weights.ts` NO aparece.
5. `verify-simplicity.sh` (con `VERIFY_COMMIT_GATE=1`) → verde (el gate de eval ya PASA).
