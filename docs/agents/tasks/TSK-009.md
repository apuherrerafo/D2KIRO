## Contexto
Depende de TSK-005 a TSK-008 (los 4 `SignalScorer` ya deben existir). Este ticket cierra la
tubería de 5 etapas de C3 (`docs/specs/SPEC.md` §C3): candidatos → señales (ya implementadas) →
**mezcla → orden → explicación**. Es el riesgo central declarado del proyecto — requiere más
juicio que un ticket acotado, por eso queda en `claude-code` en vez de `codex`.

## Qué construir
1. **Candidatos**: todos los héroes − baneados − ya elegidos (ambos lados).
2. **Mezcla**: normalizar cada `SignalContribution.raw` a 0-100, aplicar `SCORING_WEIGHTS_V1`
   (counter 0.40, patch_meta 0.25, team_synergy 0.20, role_gap 0.15 — deben sumar exactamente
   `1.0`, con prueba unitaria dedicada), sumar. **`raw: null` no vota neutro** — su peso se
   redistribuye proporcionalmente entre las señales con dato.
3. **Orden**: top 3 candidatos → 1 principal (`rank: 1`) + 2 alternativas (`rank: 2`, `rank: 3`).
4. **Explicación**: una frase corta en español por sugerencia, derivada de las `explanation` de
   cada señal — no un texto genérico desconectado de por qué salió esa sugerencia.

## Salida exacta a producir
```ts
interface Suggestion {
  hero: HeroId; rank: 1 | 2 | 3; score: number;
  signals: SignalContribution[]; // siempre las 4, incluidas las que dieron null
  reason: string; confidence: 'alta' | 'media' | 'baja';
}
interface SuggestionSet {
  schema: 'suggestions/v1'; sessionId: string; basedOnSeq: number;
  suggestions: Suggestion[]; degraded: DegradationFlag[]; computedInMs: number;
}
type DegradationFlag = 'stale_meta' | 'partial_signals' | 'unconfirmed_state' | 'unknown_format';
```

## Reglas de confianza y error (obligatorias)
- `confidence: 'alta'` = las 4 señales con dato y meta fresca. `'media'` = una señal en `null` o
  meta vencida. `'baja'` = dos o más señales en `null`. **Una sugerencia `baja` se muestra
  igual**, marcada como tal — nunca se calla el sistema durante un draft.
- Cálculo completo cortado a 500ms duros (presupuesto normal 300ms): si se corta, se devuelve lo
  que haya con `degraded: ['partial_signals']`, nunca se bloquea el push.
- Un scorer que lanza excepción cuenta como `raw: null` para esa señal — las otras 3 siguen.
- Sin candidatos válidos → `suggestions: []` + flag explícito, no un error del sistema.
- Cache de meta vacío (primer arranque) → sugiere solo con las heurísticas, `confidence: 'baja'`.

## Aceptación
- Prueba unitaria: los 4 pesos de `SCORING_WEIGHTS_V1` suman exactamente `1.0`.
- Prueba con una señal en `null`: el peso se redistribuye proporcionalmente, no se trata como 0.
- Prueba de rendimiento: `computedInMs` bajo 300ms en el caso normal.
- Cada `Suggestion.reason` es trazable a las 4 `signals` de esa sugerencia — el criterio de
  aceptación 2 del SPEC exige que el usuario pueda explicarla mirando el desglose.
