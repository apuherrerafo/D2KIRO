## Contexto (ticket autocontenido)
Proyecto: dota2coach. Origen: `/blueprint` de Fase 5, `docs/specs/SPEC.md` §12.7 (tabla `accounts`
+ migración `0005_accounts.sql`) y §12.17 (ticket 1 de Bloque A). Primer ticket de la fase — no
depende de ningún otro. El proyecto es hoy de un solo usuario de facto: el `account_id` de Steam
vive como una fila de la tabla genérica `settings` (`key = 'steam_account_id'`). Este ticket crea
la tabla real de cuentas y migra ese único dato existente, **sin cambiar ningún comportamiento
observable todavía** — nadie usa `accounts` hasta el ticket 5.

CREATE TABLE IF NOT EXISTS `accounts` (
	`steam_account_id` integer PRIMARY KEY NOT NULL,
	`personal_baseline_winrate` real,
	`created_at` text NOT NULL
);
--> statement-breakpoint
INSERT OR IGNORE INTO `accounts` (`steam_account_id`, `personal_baseline_winrate`, `created_at`)
SELECT CAST(s.`value` AS INTEGER),

--> statement-breakpoint
DELETE FROM `settings` WHERE `key` IN ('steam_account_id', 'personal_baseline_winrate');

## Casos a probar (S6, dato real de migración, no fixture inventado)
1. `settings` con una fila `steam_account_id` válida (solo dígitos, rango Steam32) → `accounts`
   termina con exactamente 1 fila, ese `steam_account_id`, `personal_baseline_winrate: null`
   (no existe esa clave en `settings` hoy — hallazgo real de `/blueprint`, SPEC.md §12.15-E), y la
   fila de `settings` se borra.
2. `settings` sin esa clave (checkout limpio) → `accounts` queda vacía, la migración **no falla**.
3. `settings` con un valor corrupto (`"abc123"`, negativo, fuera de rango Steam32) → se descarta
   por el filtro `GLOB`/`BETWEEN`, `accounts` queda vacía, sin excepción.
4. `INSERT OR IGNORE` es idempotente: correr la migración dos veces no duplica ni falla.

## Fuera de alcance (explícito)
- Nada usa `accounts` todavía — ningún query, ninguna ruta. Eso es el ticket 5 (`routes/account.ts`)
  en adelante.
- `hero_pool`/`team_groups` no cambian en este ticket — eso es TSK-095/TSK-105.
- No se loguea ni se anota en `journal.md`/este ticket el valor real de ningún `steam_account_id`
  migrado (regla de 1b, security.md).
