## Contexto
Depende de TSK-001 (esqueleto), TSK-004 (reductor) y TSK-009 (motor). Este ticket cablea todo lo
anterior detrás de la API real de `apps/engine` — es sensible a seguridad (token, binding,

## API a implementar (SPEC §3) — `apps/engine`, escuchando únicamente en `127.0.0.1`

### HTTP
| Método | Ruta | Cuerpo / respuesta |
|---|---|---|
| `POST` | `/ingest/draft-event` | `DraftEventEnvelope` → `202 { accepted: boolean, rejected?: RejectionReason }` |
| `GET` | `/api/health` | `{ status, uptimeMs, activeSessions }` |
| `GET` | `/api/heroes` | `HeroMeta[]` (con `img_url`) |
| `GET` | `/api/meta/status` | `{ syncedAt, isStale, lastSync }` |
| `POST` | `/api/meta/sync` | `202 { syncId }` — asíncrono, no bloquea (invoca el sincronizador de TSK-003) |
| `POST` | `/api/session/manual` | Mismo `DraftEventEnvelope`, `source: 'manual'` |

### WebSocket — `/ws/draft`
```ts
interface ServerMessage {
  schema: 'draft-ws/v1';
  type: 'snapshot' | 'draft_state' | 'suggestions' | 'capture_status' | 'error';
  seq: number; sentAt: string;
  payload: DraftState | SuggestionSet | CaptureStatus | ErrorPayload;
}
interface ClientMessage {
  schema: 'draft-ws/v1'; type: 'hello' | 'ping'; sessionId?: string;
}
```
**Orden garantizado tras cada evento aplicado**: primero `draft_state`, después `suggestions`.
Al recibir `hello`, el servidor **siempre responde con una instantánea completa**, nunca deltas.

## Seguridad (§5 — gate, no checklist)
- `apps/engine` se ata a `127.0.0.1`. Un binding a `0.0.0.0` es FAIL automático de revisión.
- `POST /ingest/draft-event` exige la cabecera `x-capture-token`, generada al arrancar el motor,
  leída desde variable de entorno. Sin token en el repo (ni literal ni default de fallback).
- Rate limit: 20 eventos/segundo por sesión en `/ingest/draft-event`; el exceso se descarta con
  `429`.
- Validar todo `DraftEventEnvelope` entrante en el borde antes de pasarlo al reductor (TSK-004).

## Aceptación
- `GET /api/health` responde correctamente desde `127.0.0.1`.
- Un `POST /ingest/draft-event` sin `x-capture-token` es rechazado.
- Más de 20 eventos/segundo en la misma sesión producen `429` para el exceso.
- Tras aplicar un evento válido, el cliente WebSocket recibe `draft_state` antes que
  `suggestions`, siempre en ese orden.
- `hello` siempre recibe un `snapshot` completo, nunca un delta.
