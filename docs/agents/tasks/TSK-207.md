## Contexto

`journal.md` evt-224: el corpus tiene `pro_drafts.patch = "60"` (id numérico de OpenDota) y
`meta.patchStats` tiene `"7.41e"` / `""`. `patchMetaScorer` filtra `row.patch === state.patch` →
`patch_meta` es **100% `null`** en todo el backtest. No es un bug de producción (los drafts en vivo
llevan el patch semántico); es fidelidad del backtest. 9.1 no puede calibrar `patch_meta` sin
arreglar esto.

## Alcance (SÓLO `scripts/eval/` + `scripts/stats/` — NO toca `apps/engine`)

1. **`scripts/eval/types.ts`**: `ReplayMeta` gana `patchOverride?: string`.
2. **`scripts/eval/replay.ts`**: cuando `meta.patchOverride` está, `state.patch = meta.patchOverride`
   en vez del patch crudo del corpus. Sin él → comportamiento actual.
3. **`scripts/eval/run.ts`** y **`scripts/stats/profile-signals.ts`**: calculan el override como
   **la moda de `patchStats[*].patch` que no sea `""`** (hoy `"7.41e"`) y lo pasan a
   `buildReplayCases`.
4. **`scripts/eval/report.ts`**: el reporte imprime una línea nueva: "patch del backtest forzado a
   `<override>` (§16.4) — el backtest asume que el meta vigente aplica al draft".
5. **`docs/adr/ADR-002`**: agregar una nota (no supersede — es una consecuencia dentro del mismo
   ADR): el backtest fuerza el patch actual sobre el `state`; coherente con ADR-002/C4 porque el
   snapshot no es point-in-time de todos modos.
6. **Re-generar**: `bun run scripts/stats/profile-signals.ts` y `bun run eval` → nuevo
   `signal-profile.json` (con `patch_meta` votando) + nuevo `v6-measured.json`. **Ese
   `v6-measured.json` reemplaza al de `0130e9f` como baseline de referencia del `--enforce` de
   9.1** — anotar el nuevo commit en `journal.md`.

## Criterios de aceptación

1. `scripts/eval/replay.test.ts`: fixture con `patchOverride: "7.41e"` → todos los `ReplayCase`
   tienen `state.patch === "7.41e"`; sin él → el patch crudo.
2. `bun run scripts/stats/profile-signals.ts` real → `signal-profile.json` con
   `patch_meta.rawNullRate < 1` y `realizedInfluence > 0`.
3. `bun run eval` real → `v6-measured.json` con `patch_meta` participando en Benchmark B; el
   reporte imprime la línea del patch forzado.
4. `git diff --name-only` **no muestra ningún archivo de `apps/engine/` ni `apps/web/`**.
5. `(cd scripts && bun test)` verde. `verify-simplicity.sh` verde.
