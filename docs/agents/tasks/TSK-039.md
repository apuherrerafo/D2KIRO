## Contexto (ticket autocontenido)
Proyecto: dota2coach. Origen: decisión de arquitectura de deploy (`docs/agents/journal.md`
evt-20260801-018). Depende de TSK-037 (el middleware debe correr antes de los rewrites, para que
también proteja las rutas proxeadas hacia el motor).

**Por qué es obligatorio, no opcional**: la app es single-tenant, sin concepto de cuentas/dueño.
Sin esto, cualquiera con la URL pública podría leer y ESCRIBIR datos (hero pool, equipos) de la
única instancia. Es la mitigación que hace aceptable el resto del deploy -- sin ella, no se
despliega.

## Diseño
- Middleware de Next.js (`apps/web/middleware.ts`) con Basic Auth contra dos variables de entorno
  de servidor: `SITE_ACCESS_USER` / `SITE_ACCESS_PASSWORD`.
- Comparación de credenciales en **tiempo constante** vía `crypto.timingSafeEqual` (built-in de
  Node -- cero dependencias nuevas, no hace falta pasar por `/gear-up`).
- El middleware corre **antes** de `rewrites()` -- protege tanto el sitio como las rutas
  proxeadas hacia el motor (TSK-037). Sin esto, el proxy sería un bypass de la autenticación.
- Si `SITE_ACCESS_USER`/`SITE_ACCESS_PASSWORD` no están definidas, el middleware queda
  **deshabilitado** -- el uso local sigue sin ninguna fricción, regresión cero.
- **Excepción obligatoria**: `GET /healthz` (nueva, servida por `apps/web`) queda fuera del
  middleware -- es la ruta que usa el healthcheck de Railway (`railway.json`, TSK-040), llega sin
  credenciales. Internamente hace `fetch` a `${ENGINE_INTERNAL_URL}/api/health` -- confirma que
  Next está arriba Y que el engine local responde, no solo lo primero (hallazgo de revisión de
  Codex: fijar la ruta exacta antes de implementar, no dejarlo implícito).

## Fuera de alcance
- Cualquier sistema real de cuentas/usuarios -- eso es multi-tenancy, fase futura aparte con su
  propio `/kickoff`, no se mezcla acá.
- Rate limiting del propio middleware -- Basic Auth alcanza para el alcance de este deploy
  (instancia privada de un solo usuario).

## Aceptación
- Sin las variables de entorno definidas, correr local (`bun run dev`) no pide ninguna credencial
  -- regresión cero.
- Con las variables definidas, cualquier ruta (sitio o `/engine/*` proxeada) exige Basic Auth
  válido antes de responder -- probado con credenciales correctas, incorrectas, y ausentes.
- `GET /healthz` responde sin credenciales, y refleja de verdad el estado del engine local (no
  solo "Next está vivo").
