## Alcance

### `apps/web/features/draft-feedback/DraftFeedbackBox.tsx`
- Un `<textarea>` + botón "Enviar reporte", mismo sistema de diseño que `ManualEntryPanel`
  (`BUTTON_PRIMARY`, clases `surface-*`/`content-*`).
- Al enviar: lee el `draftState` y `suggestions` **actuales** del store de Zustand (mismo store
  que ya usa `DraftView`, `useDraftStore`) en el momento del click -- nunca un valor stale
  cacheado de un render anterior.
- POST a `/api/session/{sessionId}/feedback` con `{ comment, draftState, suggestions }` -- mismo
  patrón de `fetch` que `manual-entry.ts` (`LOCAL_DRAFT_ENGINE_HTTP_BASE_URL`), función propia,
  no duplicar `postEvent`.
- Mientras está enviando: botón deshabilitado + "Enviando..." (mismo patrón que
  `ManualEntryPanel`). Un fallo de red se captura y muestra un mensaje de error, nunca deja el
  botón colgado en "Enviando..." para siempre (mismo hallazgo real que ya corrigió
  `ManualEntryPanel` -- no repetirlo).
- En éxito: limpia el textarea, muestra una confirmación breve ("Reporte guardado") que
  desaparece sola o al escribir de nuevo -- no un `alert()`.
- `comment` vacío -- el botón "Enviar reporte" está deshabilitado, no se manda nada (nunca un
  reporte en blanco).

### Ubicación (`DraftView.tsx`)
Se monta en `ActiveDraftState`/`DegradedDraftState`, junto al botón "Entrada manual" agregado en
TSK-049 -- mismo criterio: es información de apoyo durante un draft en curso, no antes ni después.

## Fuera de alcance
- El endpoint que recibe el POST (ya hecho, TSK-051).
- Cualquier pantalla para *leer* los reportes ya guardados -- eso lo hace Claude Code en la

- Adjuntar capturas de pantalla o cualquier medio además de texto -- fuera de alcance de esta
  primera vuelta.

## Aceptación
- Con un draft activo, escribir un comentario y apretar "Enviar reporte" persiste la fila
  correcta en `draft_feedback` (verificable con `GET /api/feedback`), incluido el `draftState`/
  `suggestions` real del momento exacto del envío.
- Un fallo de red muestra un mensaje de error explícito, nunca un botón colgado.
- El textarea se limpia después de un envío exitoso.
- Convenciones de `.claude/rules/web.md` respetadas (sin `any`, sin ternarios para renderizado
  condicional, sin funciones anónimas inline como props, arquitectura por features).
- `bun test` sin regresiones, `tsc --noEmit` limpio, `bun run lint` sin errores nuevos,
  `verify-simplicity.sh` PASS.
