## Contexto

La señal `counter` está estructuralmente muerta: `RELATIONSHIP_MIN_GAMES = 200` en
`relationship-index.ts` descarta ~93% de los pares héroe-vs-héroe, así que `counter.raw` es `null`
en la mayoría de los drafts (caso real: el Copilot recomienda Huskar como last-pick con un Ancient
Apparition revelado del rival). Fase 8A la rehabilita con dos capas: **piso curado** (este ticket)
+ capa estadística arreglada (`TSK-185`). Contrato en `SPEC.md` §14.4, reglas de fase en
`.claude/rules/` ("Fase 8" en `engine.md`, `security.md`, `testing-seams.md`) y `CLAUDE.md`
("REGLAS DE FASE 8").

Primer eslabón de 8A (los otros: `TSK-184` `observedWinrate`, `TSK-185` el scorer, `TSK-186`
`mix.ts`). 8B (`TSK-187`) es independiente.

## Alcance

1. **`apps/engine/src/signals/hero-counters.json`** (nuevo) — keyed por la *víctima* (`HeroId` →
   `CuratedCounter[]`), `{ "<victimId>": [{ "vs": <rivalId>, "level": "hard"|"medium", "why": "<texto visible>" }] }`.
   Borrador de **~30 héroes** (los más pickeados) armado por **deep research** de conocimiento
   público estándar de Dota 2. **No se scrapea Dotabuff** (ToS + Cloudflare). El usuario revisa y
   corrige el JSON **antes del merge** — es dato de dominio, no código.
2. **`apps/engine/src/signals/hero-counters.ts`** (nuevo):
   - `export interface CuratedCounter { vs: HeroId; level: "hard" | "medium"; why: string }`.
   - `export function loadHeroCounters(): Map<HeroId, CuratedCounter[]>` — mismo patrón que
     `loadHeroPositions()`. Lee el JSON, valida en el borde:
     - descarta entrada sin `vs` entero, con `level` fuera de `{"hard","medium"}`, con `why` vacío
       o no string, con `vs` que no exista en `CURATED_HERO_IDS` (`validate-drafts.ts`), o
       duplicada (`vs` repetido en la lista de una misma víctima).
     - archivo ausente / JSON inválido / forma de raíz inesperada → **`Map` vacío**, nunca lanza
       (criterio literal de `loadHeroPositions()` con archivo malformado).
   - `loadHeroCounters` exportada por separado para probarla con fixtures sintéticos.
3. **`apps/engine/src/signals/hero-counters.test.ts`** (nuevo) — fixtures **inline**, jamás el
   archivo real (S9). Casos: JSON bien formado → `Map` con las entradas; `level` inválido / `why`
   vacío / `vs` desconocido / duplicado → esa entrada se descarta, el resto sobrevive; archivo
   corrupto / raíz que no es objeto → `Map` vacío sin excepción.

## Criterios de aceptación

1. `bunx tsc --noEmit` limpio en `apps/engine`. `bun test` verde. `bash scripts/verify-simplicity.sh`.
2. `loadHeroCounters()` sobre un fixture válido devuelve el `Map<HeroId, CuratedCounter[]>` esperado.
3. Cada forma de entrada malformada (§14.4) se descarta individualmente sin tirar las demás.
4. Archivo ausente / JSON roto / raíz no-objeto → `Map` vacío, cero excepción.
5. Ninguna prueba lee `hero-counters.json` real.
6. El JSON borrador queda listo para revisión del usuario (comentario `// TODO: revisión de dominio
   pendiente` o nota en el PR) — **no se mergea 8A completo sin ese visto bueno**.
7. `SignalId`, `weights.ts`, `RAW_RANGE`, `relationship-index.ts` — **sin tocar** en este ticket.
