## Contexto

SPEC.md §16.7–§16.8. El corazón de 9.1: se termina la redistribución candidate-specific y se pasa
a **mezcla por estado**, con `EvidenceCoverage`/`GuessingIndex` y calibración empírica cableada.
Con el candado de regresión cero, con la calibración en fallback y las opciones legacy, el motor
reproduce V6 **byte a byte**.

## Alcance

Reemplaza `weightedContributions` / `mixScore` / `computeConfidence` en `mix.ts`:

1. **`availableSignals(state, meta, options): Set<SignalId>` — `A(S)`** (§16.7 punto 1):
   `position_fit` siempre salvo `localSide === "unknown"`; `counter` si `revealedEnemyPicks > 0`
   o hay un counter curado sobre un baneado; `team_synergy` si `own picks > 0`; `patch_meta` si
   la calibración de `patch_meta` no es null (o, en modo legacy, si su `raw` no es null);
   `hero_pool_fit` si `meta.heroPool` no vacío; `archetype_fit` si hay `archetypeIntent`.
2. **Redistribución por estado**: `wᵢ' = SCORING_WEIGHTS_V6[i] / Σ_{j∈A(S)} SCORING_WEIGHTS_V6[j]`
   — el denominador se calcula **una vez por estado**, igual para todo candidato.
3. **`μᵢ(S)`**: primera pasada por los candidatos del estado → junta `normalizedᵢ(h)` no nulos por
   señal; `μᵢ(S)` = media. Si ninguno tiene dato → `μᵢ(S) = 50` (**único neutro del pipeline,
   nunca escrito en `raw`**).
4. **`contributionᵢ(h)`** (segunda pasada): `i ∉ A(S)` → 0; `rawᵢ(h) ≠ null` →
   `wᵢ'·normalizedᵢ(h)`; `rawᵢ(h) = null` → `wᵢ'·μᵢ(S)`. `signals[i].weighted = contributionᵢ(h)`.
5. **`score(h) = Σ contributionᵢ(h)`** ∈ `[0,100]`.
6. **`EvidenceCoverage(h) = Σ_{i∈A(S), rawᵢ(h)≠null} wᵢ'`**; **`GuessingIndex = 1 − EvidenceCoverage`**.
   `Suggestion` gana `evidenceCoverage`/`guessingIndex`.
7. **`computeConfidence`** deriva de `EvidenceCoverage`: `alta` si `≥ 0.75` y meta no stale;
   `media` si `≥ 0.5` o meta stale; `baja` si `< 0.5`.
8. **`normalize()`** de `mix.ts` pasa a llamar `calibratedNormalize(signal, raw, bracket,
   MODULE_CALIBRATION)` (de TSK-209). El `bracket` del estado: si `state` no tiene bracket, usar
   `global`. `RAW_RANGE` **no se borra** — es el fallback dentro de `calibratedNormalize`.
9. `enrich()` (TSK-209) se aplica a cada `SignalContribution` antes de la mezcla, para poblar
   `normalized`/`evidenceConfidence`.
10. `BuildSuggestionsOptions` gana `calibration?: Calibration` (inyectable para tests; ausente →
    `MODULE_CALIBRATION`). Modo legacy para el candado: una opción interna
    `_legacyMixMode?: boolean` (o el candado se prueba llamando a la función vieja preservada
    como `mixScoreV6` sólo-test).

## Criterios de aceptación

1. **Candado de regresión cero — dos pruebas en `mix.test.ts`** (números concretos):
   - calibración en fallback + `A(S)` = "señales con `raw ≠ null` para el candidato" + sin
     `μᵢ(S)` ⇒ `mixScore` sobre un set fijo de `SignalContribution[]` da el **mismo número exacto**
     que V6.
   - `buildSuggestions` sobre un fixture fijo con opciones legacy no mueve el ranking ni un
     `signals[].weighted`.
2. **`μᵢ(S)`**: estado con dos candidatos, uno con `counter.raw` numérico y otro `counter.raw:
   null` → el segundo recibe `weighted = w'·μ` (no 0, no excluido); su `raw` sigue `null` en el
   desglose.
3. **`EvidenceCoverage`**: candidato 3/3 señales de `A(S)` con dato → `evidenceCoverage === 1`;
   1/3 → `= w'` de esa señal; `guessingIndex = 1 − evidenceCoverage` en ambos.
4. **Degradación S18**: `buildSuggestions` con `calibration` corrupta → ranking byte-idéntico a V6.
5. **Sensibilidad de calibración**: con `percentiles.json` fixture donde `counter` tiene rango
   `[−0.05, 0.05]` (angosto) vs `RAW_RANGE.counter [−0.12, 0.12]`, un candidato countereado baja
   más en el ranking calibrado que en el legacy — prueba dedicada contra `buildSuggestions`
   completo (mismo criterio que §10.9-7).
6. `bunx tsc --noEmit` limpio ambos paquetes; `bun test apps/engine` verde. `git diff
   --name-only`: sólo `mix.ts`/`mix.test.ts`. **`weights.ts` NO aparece.**
